# Phase 2 - CLIP Representation Layer

Measured shapes, versions and device: see `phase_2_verified_output.md` (generated by
`scripts/test_clip_encoder.py`). Values below describe design intent; the generated file is the evidence.

1. **Why CLIP.** It is pretrained on large image-text data, so image and text already share an embedding
   space. Composed retrieval needs both modalities; training a ViT from scratch is neither necessary nor feasible on 4 GB VRAM.
2. **Checkpoint.** `openai/clip-vit-base-patch16` via Hugging Face `transformers` (OpenAI weights). Chosen over
   OpenCLIP because the library documents access to per-token hidden states; OpenCLIP can be swapped in
   later by editing `clip_encoder.py` only.
3. **Why ViT-B/16.** Small enough for the GPU, 16x16 patches give 14x14=196 spatial tokens at 224x224, which
   is the granularity Phase 4 cross-attention needs.
4. **Visual encoder output.** Global embedding (CLS -> post-LN -> projection, L2-normalized), raw CLS and
   patch hidden states (768-d), and projected patch embeddings (512-d, not normalized).
5. **Text encoder output.** Global embedding (EOS token -> projection, L2-normalized), token-level embeddings
   (512-d, not normalized), and the attention mask.
6. **Global vs token/patch.** Global vectors summarize a whole image/sentence and suit nearest-neighbour search.
   Token/patch vectors keep *where* and *which word*, which global vectors discard.
7. **Why patches are kept.** Phase 4 uses text tokens as queries over image patches to decide which regions a
   modification refers to, and which stay unchanged.
8. **Why text tokens are kept.** Each word ("blue", "sleeveless") can attend to different patches. Padded
   positions must be masked (e.g. in mean pooling) using `attention_mask`.
9. **Why frozen now.** Phase 2 is representation extraction; the baseline (Phase 3) must isolate what the new
   modules add before any backbone fine-tuning is considered.
10. **How Phase 3 uses it.** `encode_image(...).global_embed` for reference and target, `encode_text(...).global_embed`
    for the caption; a simple fusion of these forms the baseline query. Patch and token outputs stay unused until Phase 4.

## Design choices and limitations
- Patch embeddings reuse CLIP's own final LayerNorm and projection. CLIP was trained to align only the CLS
  vector, so patch embeddings are not guaranteed to be semantically aligned. Phase 4 may replace this with a learnable W_v.
- Only the CLS/global path is L2-normalized; patch and token outputs are not.
